# 配置与故障处理

## 模型

首次打开可先连接 QQ 或选择「仅使用桌面聊天」，再进入「环境配置」。使用 DeepSeek 时，接口和模型已有默认值，输入 API Key 后点「测试通过后保存」。切换服务时会先测试填写的模型，验证通过后启用。成功后点「去桌面聊天」。选「仅保存」可以直接启用填写的配置。

配置完成后，这里显示模型名称、接口地址、密钥保存状态和连接验证结果。「修改配置」打开编辑器，使用当前地址已保存的凭据时，可以点「更换密钥」。连接测试失败后，可直接在摘要里重试。

选择「本机模型服务」或「其他 OpenAI 兼容服务」会展开接口地址与模型名称。填写兼容 Chat Completions 的服务地址以及实际模型 ID。本机可使用 `http://127.0.0.1:端口/v1`，远程接口需要 HTTPS。「高级选项」可调整上下文大小、输出预算、任务思考强度以及接口是否需要密钥。

纯陪伴关闭思考，单次回复预算最多 512 tokens。受控助理使用设置中的思考强度与最大输出。DeepSeek 的关闭选项明确发送 `thinking.type=disabled`，避免供应商默认值造成额外延迟。其他兼容服务的 reasoning 选项取决于其协议支持。

连接测试会使用一次实际 API。日常会话、后台记忆与群内自主判定均可能产生费用。界面统计供应商返回的 token 用量，不能保证是完整账单；请求失败或供应商未返回 usage 时尤其如此。

密钥按供应商和接口 origin/path 绑定。更换地址不会把旧密钥带到新地址。HTTP 重定向拒绝跟随。应用不从 `.env`、旧版目录或进程环境变量自动寻找密钥。

## OneBot v11 / NapCat

**本机 NapCat 扫码**

1. 安装向导中选择「由 ChatDS 下载」或「使用已经安装的 NapCat」。下载在安装结束、第一次启动 ChatDS 时开始。也可以在应用的「环境配置 → 配置 NapCat」里选择已有目录或导入离线的 `NapCat.Shell.zip`。下载和离线导入均限定 **v4.18.42**，安装前校验大小及 SHA-256。已有目录应选已解压的安装目录，如有 `config/webui.json` 也可以选其 `config` 目录。[原包留档](https://github.com/XingYunStar/NapCatQQ/releases/tag/v4.18.42)
2. 本机需要 Windows QQ 客户端。若界面提示缺少 QQ，可点「下载 Windows QQ」，安装后再点「启动 NapCat」或重启 ChatDS。程序每次启动会检查已关联的本机 NapCat，已有运行实例会继续使用。需要按原方式启动的外部部署，可使用本机 WebUI 登录链接或手动连接 OneBot。
3. 二维码出现后，使用**给小鱼使用的普通 QQ 账号**扫码并在手机确认。ChatDS 会准备本机消息接口并核对登录账号，完成后显示「QQ 在线」。登录仍有效时会直接连接。在 QQ 管理中可另设**个人主号**，用来共享桌面记忆和使用受控助理。

只使用桌面聊天时，可以一直保留未关联状态。「环境配置」中的可选入口始终可以用来配置 NapCat 或其他 OneBot 服务。侧栏「QQ 管理」、聊天页的 QQ 会话、聊天名单和好友申请只在消息服务在线且机器人账号核对通过后出现。断线时这些入口会收起，会话历史保留，在配置页可以重新连接。

登录二维码在本机生成。NapCat 管理凭据仅在读取 WebUI 和处理登录时使用，消息接口令牌保存在本机凭据库。取消目录关联只清除保存的路径，已连接的其他 OneBot 服务可继续使用。

**已有 OneBot v11 服务**

在服务端开启正向 WebSocket、消息段数组和非空 Access Token。「手动连接 OneBot 服务」中填写服务地址、机器人 QQ、个人主号和令牌，再点「保存并连接」。本机地址形如 `ws://127.0.0.1:3001`，远程服务使用 `wss://`。可在「谁可以和小鱼聊天」单独保存允许的私聊和群号。

首次扫码接入默认允许好友私聊，可在「谁可以和小鱼聊天」关闭；陌生私聊和群需要加入名单。旧配置沿用已保存的名单。每位好友拥有独立记忆，群里的事实属于该群。只有桌面和主号私聊可使用任务工具；授权在桌面完成。

主号可发 `/状态`、`/status`、`/停止` 或 `/stop`。在桌面可以通过或拒绝当前在线机器人账号的好友申请。遇到提交后断线，可先在 QQ 核实，再移除本机提醒。旧版没有记录接收账号的申请也请在 QQ 中处理。聊天权限仍由私聊和群名单决定。

开启某群的无需 @ 模式后，每群默认每小时最多判定 60 次、回复 6 次，至少间隔一分钟。全局每日自主判定预算为 100,000 tokens。命中配额后只同步消息。在群里直接 @ 小鱼或引用她的消息之后，同一人的连续补充也能进入本轮对话。

OneBot 无法保证所有网络断线下的 exactly-once 发送。已发出但没有得到确认的操作标记「结果未知」，由用户在 QQ 核实，不自动重试。说说接口依赖 QQ 空间与服务端能力，属于实验功能；默认关闭，只支持经桌面确认的纯文字正文。

## 本地文件

默认数据目录：`%APPDATA%\ChatDS`，可从设置打开。

| 内容                                       | 文件或目录                                   |
| ------------------------------------------ | -------------------------------------------- |
| 普通配置与上一版本备份                     | `config.json`、`config.json.bak`             |
| 加密密钥与 OneBot 令牌                     | `secrets.bin`                                |
| 原始聊天、记忆、来源、摘要、发送状态与配额 | `chatds.sqlite`，运行时有 WAL/SHM            |
| 每个身份的受控文件区                       | `workspaces/`                                |
| 已导入技能快照                             | `skills/`                                    |
| 导入前备份                                 | `backups/`                                   |
| 运行日志                                   | `activity.log`、`activity.log.1`，各约 1 MiB |

聊天文本、人设、记忆和工作区文件保存在本机，数据库没有额外的应用层加密。使用模型时必要上下文会发到你配置的供应商；网页工具会访问用户指定的公开站点。不要把数据目录放入公开仓库。

关闭窗口后留在托盘；完全退出使用托盘菜单。登录启动可在设置切换。复制或备份数据库前应完全退出应用；不要只复制运行中的 `.sqlite` 文件而遗漏 WAL。

高级配额可在应用完全退出后编辑 `config.json`，启动会严格校验字段。`memory.dailyTokenBudget` 默认 50,000，涵盖事实提取与摘要；设为 0 可暂停后台模型调用，明确「记住」仍可在本机保存。恢复时保留的后台任务会继续处理。`memory.automatic=false` 关闭自动事实提取，摘要仍受同一个后台预算约束。

## 人设、技能与旧数据

在「小鱼人设」可新建角色，或导入酒馆 JSON / PNG。卡中分别保存名字、头像标识、描述、性格、场景、开场白、示例对白和作者。导入后先预览并保存到角色库。设为默认会影响所有跟随默认角色的会话，也可从聊天标题栏为当前桌面、QQ 私聊或群聊单独选一张卡。旧版人设会出现在首张卡中。空桌面会话会显示所选角色的开场白；切换角色后已有消息保留原署名。可将保存的角色导出为 JSON 或 PNG，交换图片卡时会带上净化后的缩略图。

同页的「我的人设」用于写自己在对话中的身份，选定后用于对应的桌面或主号私聊。世界书用于保存地点、背景和人物关系，可按会话勾选生效。不同 QQ 好友之间的记忆仍分别保存。角色资料在每次模型请求时重新载入；程序根据实际账号、模式和桌面授权决定可用工具。角色文件里的脚本、系统提示覆盖和工具设置不会执行。

技能导入选择包含 `SKILL.md` 的普通目录；frontmatter 需要 `name` 和 `description`。示例位于 `examples/skills/notes`。修改源目录后需要重新导入。脚本不会因出现在技能目录中而自动执行。

旧数据必须由用户选择文件并确认预览。只支持旧版 version 1、含 `rooms` 与 `memories` 的 JSON。私聊事实只有 scope 与 senderQQ 一致才导入个人记忆。群聊归属不明的历史作为未核实记录保存，不猜测发言人。人设与 API Key 需要重新配置。同一文件哈希只允许导入一次，导入前会创建数据库备份。

「忘记」删除模型可检索事实，排除原始来源、用过该事实的后续模型回合及相关摘要，清空待提取任务防止复活。原始聊天仍在界面；这不等于删除磁盘上的历史记录与备份。更正可以在聊天中说明；自动更正依赖模型正确识别来源，仍建议在记忆页核对。

## 常见问题

- **密钥已保存但仍提示未配置**：检查接口地址和 provider 是否改变；不同地址独立保存密钥。
- **凭据无法解密**：可能换了 Windows 用户或系统加密环境。完全退出，备份 `secrets.bin`，将其移到数据目录外，再启动并重新输入密钥。不要覆盖唯一备份。聊天数据库与普通配置可保留。
- **配置损坏导致无法启动**：完全退出，备份损坏文件，检查 `config.json.bak`；恢复前先保留两份文件。应用不会默默重置并覆盖旧配置。
- **QQ 无回应**：检查账号核对结果、令牌、白名单、群 @ 或自主开关、暂停状态与配额。仅同步的群消息不会调用模型。
- **Docker 不可用**：普通聊天可正常使用。检查 Linux 容器模式和专用镜像，再在桌面重新检查。应用不会降级到宿主机执行命令。
- **停在生成阶段**：可停止当前会话；模型请求有超时。实际阶段日志不会暴露原始思维链。
